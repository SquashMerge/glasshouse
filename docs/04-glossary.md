# Glossary

Living doc. Keep it short. Update when you add a term, rename something, or notice two names being used for the same thing.

## Product identity

### Glasshouse
The current product name and Licensed Work named by the repository-root BSL 1.1 `LICENSE`; Glasshouse by SquashMerge is the same software previously developed under the Astraea name. Runtime, configuration, API, and data identifiers were mechanically renamed to Glasshouse; backward compatibility with old Astraea identifiers is not promised.

## Observability

### Trace
A request through your agent end-to-end. Top-level observability unit. Schema: `apps/api/src/schemas/traces.ts`.

### Observation (preferred over "span")
One unit of work inside a Trace — one row per OTel span. Schema: `apps/api/src/schemas/traces.ts`. Has a `type`:

| `type`       | Meaning                          | Detected by (`apps/api/src/db/gen-ai-attrs.ts:78`)                          |
| ------------ | -------------------------------- | ----------------------------------------------------------------------------- |
| `span`       | Generic OTel span (fallback)     | nothing else matched                                                          |
| `generation` | LLM call                         | `gen_ai.request.model` / `gen_ai.response.model` or `type ∈ {llm,chain,agent}` |
| `tool`       | Tool / retriever / embedding     | `tool.name` or `type ∈ {tool,retriever,embedding,reranker}`                   |
| `event`      | Point-in-time marker             | leftover bucket                                                                |

The four-way split is the Langfuse/LangSmith taxonomy, applied at OTLP ingest. Forward-compat: store one row shape, render off `type` later.

> **Don't say "span" when you mean "observation".** "Span" is reserved for the UI label (the "Spans" tab) and for `observation.type === "span"` specifically.

### Trace cursor
An opaque `next_cursor` that preserves an endpoint's stable keyset boundary and is not transferable to another endpoint. Trace and Observation list cursors are Project-scoped (`start_time, id`); Trace-detail and detail-SSE cursors are both Project- and trace-scoped (`start_time, observation_id`).

## Organization usage dashboard

- `/` — authenticated organization homepage. It summarizes retained Trace and Observation rows for all active and archived Projects, with `24h`, `7d`, `30d`, and `90d` UTC ranges. Counts are grouped by `start_time` and are storage-row counts, not unique events or billing values.
- `GET /v1/organization/usage` — authenticated organization-wide aggregate metadata for the dashboard. Organization scope comes only from the authenticated Actor; Admin, User, and Read-only members receive the same aggregate. It does not authorize trace/Observation detail, query, export, or other Project operations. See `docs/03-otel-ingest.md`.
- **Data through** — the usage response's `to` timestamp, displayed in UTC as the exclusive query range end. It is neither an ingestion watermark nor a last-update timestamp. **Refresh usage** refetches the selected range without navigation.

## Observability UI

- `/observability` — Traces tab + Spans tab. The "Spans" tab is really the observations table (all four types mixed); the label is a legacy holdover.
- `observabilityTabFocus` — browser history state recording the selected tab's focus intent so keyboard selection survives a protected-page remount during URL navigation. It carries no credentials or telemetry.
- `/observability/traces/$id` — Trace detail: tree of observations + detail panel.

## Prompt UI

- `/prompts` — project-scoped prompt list; `/prompts/new` creates the first immutable version; `/prompts/$slug` selects an immutable version; `/prompts/$slug/edit?from=N` starts the next version from version `N`. See `apps/web/src/routes/prompts*.tsx`.
- `POST /v1/prompts/preview` — authenticated, non-persistent Mustache rendering of system and user draft sources with supplied JSON data. See `apps/api/src/routes/prompts.ts`.
- `POST /v1/prompts/{id}/versions/rollback` — authenticated, project-scoped removal of only the latest version; restores the immediately previous version and migrates its labels. See `apps/api/src/routes/prompts.ts`.

## SSE endpoints

- `GET /v1/traces/events` → `streamTraceEvents` — broadcasts new traces. Stays open.
- `GET /v1/observations/events` → `streamObservationEvents` — broadcasts new observations. Stays open.
- `GET /v1/traces/{id}/events` → `streamTraceDetailEvents` — single trace: snapshot + filtered live observations + closes after `TRACE_COMPLETE_GRACE_MS` of inactivity.
- `GET /v1/prompt-optimizations/{id}/events` — optimization lifecycle statuses.
- `GET /v1/experiments/{id}/events` — evaluation lifecycle snapshots.

## Core entities

- **Organization** — top-level authenticated tenancy boundary. Its server-authoritative `default_project_id` names one active Project in that organization. Current Basic Auth credentials resolve to a configured username compatibility subject and one Organization; the `basic:v1` provider maps its canonical subject to a durable internal actor ID without changing the server-derived tenancy boundary.
- **Project** — organization-owned workspace and data boundary (`project_id` on stored application and observability data). A Project is `active` or non-destructively `archived`; every Organization role applies to every active Project in its Organization. Its UUID is immutable; its validated slug is unique within its organization. Non-default Projects may be permanently deleted with exact typed-name confirmation; lifecycle evidence is retained without content.
- **Actor** — a durable internal identity with an immutable ID. Compatibility `basic:v1`, organization-qualified `local:v1`, and future identity-provider subjects map to an Actor; an external email, username, or IdP claim alone is never the authorization identity.
- **Local credential** — an Organization-scoped normalized ASCII username bound to an existing durable Actor/identity, with enabled state and a salted Argon2id PHC hash plus algorithm/policy version; all password fields are NULL until first-password enrollment. Username policy: 3–64 ASCII characters, first alphanumeric, remaining alphanumeric/`.`/`_`/`-`, lowercase normalization. Newly set or changed passwords require at least 12 Unicode characters and at most 1024 UTF-8 bytes; existing shorter passwords remain valid for login until changed or reset. Provider `local:v1` uses `<organization-uuid>:<username>` as its globally unique canonical subject. See `docs/local-credentials-runbook.md`.
- **Local session** — an Organization/Actor-scoped, fixed eight-hour server-side authentication record with a one-way digest of a 32-byte opaque random cookie, credential authentication version, expiry and revocation time. `glasshouse_session` is HttpOnly, SameSite Strict, `/v1`-scoped and Secure in production; organization roles are checked at request/effect time. Browser sign-in uses separately provisioned local credentials, retains CSRF only in memory, restores the cookie session on reload, and revokes it on sign-out. Login/session/logout/self-password APIs live under `/v1/auth`; see `docs/local-sessions-runbook.md`.
- **Authentication version** — storage-managed `local_credentials.auth_version`, incremented on credential/enablement changes and bound to each session; older sessions remain invalid even after re-enabling an account.
- **OTLP ingestion credential** — organization Admin-managed, Project-bound bearer secret whose SHA-256 digest is stored server-side; the secret is returned once at creation/rotation. Any current organization Admin may rotate or revoke it. Bearer ingestion acts as the creator Actor, so losing that Actor’s authority or disabling its account stops ingestion without automatically revoking the credential. See `docs/03-otel-ingest.md`.
- **Session CSRF value** — non-bearer, session-bound value returned by `GET /v1/auth/session`, supplied as `x-glasshouse-csrf` on cookie-authenticated mutations. It is distinct from the HttpOnly session cookie.
- **Local login limit** — fixed 8-bit anonymous username bucket plus Organization-wide admission window in `local_login_limits`; bounded to 257 rows per Organization, without stored usernames or network/device metadata. Content-free login/revocation evidence lives in `local_auth_audit_events`.
- **Local bootstrap control** — the Organization-owned permanent first-Admin setup fence. An operator explicitly provisions a single-use, 24-hour token digest while no Admin exists; successful setup consumes it atomically with Admin creation. Any first Admin permanently closes the fence. `GLASSHOUSE_AUTH_BOOTSTRAP_MODE=local` skips the legacy automatic Basic owner grant on intentionally local-first installs.
- **Local account enrollment** — an Admin-provisioned, Organization/Actor-scoped first-password or password re-enrollment record. Current UI/API uses username-only `first_use` records and manual out-of-band handoff. Its code digest is single-use, revocable, and expires in 7 days. The historical `email_invitation` variant is reserved for later work, not exposed here. No public self-registration is implied.
- **Enrollment code handoff** — once-only authorized Admin response/view after provisioning/re-enrollment. The raw code is discarded on dismissal/navigation/reload, never returned by account lists, cached in query/mutation state, stored in Web Storage, logged or included in URLs. `/enroll` accepts it with the account holder's first password.
- **Local account status** — `active` means enabled with a password; `pending` means enabled but passwordless; `disabled` blocks authentication/enrollment while preserving role records. Enrollment status separately reports pending, expired, revoked or consumed.
- **First-run setup page** — `/setup`, available only while the server permits the operator-provisioned first-Admin secret. Scope/role are server-chosen; setup closes permanently after commit. `/login` uses cookies and `/access` exposes Admin controls through `/v1/admin/local-accounts` and `/v1/admin/local-enrollments`.
- **Access role** — Glasshouse's server-enforced access vocabulary: **Admin**, **User**, and **Read-only**. Admins manage organization security, local accounts, Project lifecycle, governed controls, and destructive/recovery actions; Users can perform ordinary permitted work in every active Project in their Organization; Read-only actors can inspect every active Project's evidence and content-free audit history but cannot mutate product data. Legacy `owner`/`manager`/`member` records remain compatibility projections. See `infra/db/migrations/0103_organization_role_project_access.sql`.
- **Identity provider (IdP) connection (planned P1)** — an organization-scoped BYO IdP configuration that authenticates external subjects into durable Glasshouse Users. OIDC is the first supported SSO protocol; SAML uses the same internal identity and Organization-role boundary. Provider claims require explicit server-side mapping and never grant authority by themselves.
- **Project lifecycle audit event** — content-free durable evidence of Project creation, organization-default changes, and permanent-deletion attempts/results. It keeps the deleted Project UUID without retaining Project content. See `infra/db/migrations/0033_project_default_and_deletion_lifecycle.sql`.
- **Organization actor role** — a durable Actor's organization-scoped **Admin**, **User**, or **Read-only** role. It is the source of authorization, while the legacy Basic Auth membership rows are retained only as rollout compatibility projections. See `infra/db/migrations/0051_admin_membership_project_grants_recovery.sql`.
- **Usable active Admin** — an organization-scoped Admin role with an identity that satisfies `organization_actor_is_usable_admin`. Legacy/non-local identities retain their existing behavior; a `local:v1` identity counts only with an enabled local credential and a non-NULL password hash. Final-Admin role removal, identity unlinking, and break-glass recovery share these semantics; unlinking excludes the identity being removed. Pending, revoked or expired passwordless, and disabled local accounts retain their records and roles but do not satisfy them. See `infra/db/migrations/0099_usable_local_admin_guard.sql` and `infra/db/migrations/0100_usable_local_admin_identity_unlink_guard.sql`.
- **Break-glass recovery** — a destructive, content-free-audited Admin restoration that only the explicitly configured bootstrap Basic Auth owner may invoke for its own organization after all active Admins are absent. It has a durable 15-minute cooldown, creates no credential or token, and never selects a tenant from request input. See `apps/api/src/routes/admin-access.ts`.
- **Project membership** — a legacy Basic Auth compatibility projection. It is not an effective authorization grant; durable Organization roles determine access to every Project in the same Organization.
- **Project capability** — a server-authoritative per-Project permission exposed as `can_manage` or `can_govern` alongside the effective role. The dashboard uses it for controls so compatibility-mode legacy managers retain permitted controls while strict-mode Users do not. See `apps/api/src/schemas/projects.ts`.
- **Authorization audit event** — append-only, content-free PostgreSQL evidence for workspace bootstrap, membership, lifecycle, role, and identity-provider actions. In strict mode, Admin, User, and Read-only actors may read only the permitted active Project's content-free history; archived/deleting lifecycle visibility is Admin-only. See `infra/db/migrations/0041_admin_user_read_only_authorization.sql`.
- **Execution admission** — a short-lived, durable PostgreSQL authorization record for one optimization or experiment-task provider invocation. It pins the requester and Project authorization epoch, is cancelled by revocation/demotion/archive, and bounds local provider cancellation without holding database locks across the remote call. See `apps/api/src/db/execution-admissions.ts` and `infra/db/migrations/0044_execution_admission_cancellation.sql`.
- **Execution effect claim** — the bounded PostgreSQL decision immediately before one provider dispatch, trace, metric, result, or lifecycle-event effect. It links an admission to a durable logical execution effect, whose tenant-scoped work-item/effect/operation key makes a replay resolve to the existing decision rather than duplicate the effect. A pre-existing provider or trace effect has an unknown remote outcome and is terminalized or reconciled without replay. Its commit is the logical admission boundary against revocation, not physical atomicity with a remote provider or ClickHouse. See `apps/api/src/db/execution-admissions.ts` and `infra/db/migrations/0047_durable_execution_effects.sql`.
- **Authorization lock order** — PostgreSQL authorization, membership management, audit, admissions, effects, and SSE fences lock organization membership rows, Project membership rows, Project rows, then Project audit-provenance advisory locks. Membership revocation has this same effective order because PostgreSQL locks its target row before the `BEFORE ROW` trigger; deleted Projects retain only the final UUID advisory fence. See `apps/api/src/db/project-authorization.ts` and `infra/db/migrations/0048_project_audit_lock_order.sql`.
- **SSE frame fence** — the per-frame current-membership/Project authorization transaction used for every authenticated stream comment, snapshot, data, heartbeat, status, and error delivery. Active plus queued frames are count- and byte-bounded; overflow closes and drops the queue. See `apps/api/src/lib/authorized-sse.ts`.
- **Agent (planned)** — the future project-scoped, versioned, typed evaluation target. It is introduced after the Dataset, Evaluation, identity, and execution foundations are complete.
- **Manifest (planned)** — serialized form of an Agent (prompts + tools + routing + guardrails + knowledge + deps as one atomic unit). It is a generated/exported artifact for normal SDK onboarding and a GitOps escape hatch, then pinned to Evaluation runs for bisectable regressions and atomic rollback.
- **Prompt** — immutable collection of up to one system and one user Mustache message, scoped to a Project; its canonical public ID is the Project-local slug, while `slug@version` is display-only. See `apps/api/src/db/prompts.ts`.
- **Prompt provenance** — typed `(id, version, content_hash)` from a generation observation's atomic `glasshouse.prompt.*` OTLP tuple; `GET /v1/prompt-provenance/{id}` reports whether that scoped tuple is `active`, `deleted`, or `unknown`, without source or render data. All `glasshouse.prompt.*` input attributes are stripped before metadata storage or events. See `apps/api/src/db/observation-metadata.ts` and `apps/api/src/routes/prompt-provenance.ts`.
- **Prompt tombstone** — immutable `(project_id, slug)` reservation left by a hard deletion; prevents canonical prompt ID reuse. See `infra/db/migrations/0009_prompt_management_canonical.sql`.
- **Prompt deletion audit** — immutable, content-free deletion record: project ID, internal prompt ID, slug, deleting actor, timestamp, and deleted version count. See `infra/db/migrations/0009_prompt_management_canonical.sql`.
- **Prompt optimization job** — a project-scoped GEPA request that pins a source prompt version, target message role, versioned optimization dataset snapshot, worker model configuration, and budget. Its immutable source-message snapshot supports reviewable evidence; `worker_claim_id` with `worker_lease_expires_at` gives one API replica temporary execution ownership and allows recovery after a replica crash. `metric_calls_used` records final worker telemetry when available, never inferred progress; it publishes at most one new immutable prompt version and exposes only lifecycle metadata through its SSE stream. See `apps/api/src/routes/prompt-optimizations.ts`.
- **Optimization dataset snapshot** — an immutable, job-local `dataset.version: 1` object containing a rubric/objective plus separately represented training and held-out validation examples. It is retained server-side; external job responses expose only its version, rubric, and split counts. It is not the mutable project Dataset resource. See `apps/api/src/lib/optimization-dataset.ts`.
- **Held-out validation evidence** — the candidate and source scores plus sample count from validation inputs that do not overlap the training split. Inputs with containment or at least 70% shared normalized tokens are not independent. It selects GEPA candidates and governs automatic promotion; a training score is diagnostic only. See `worker/gepa_worker.py`.
- **Optimization leakage check** — server-side normalized full-answer and material-span detection, including reordered token copies, that blocks a candidate from becoming a prompt draft or version when it copies expected-answer labels or example inputs. See `apps/api/src/routes/prompt-optimizations.ts`.
- **Review-required draft** — a safe optimization candidate retained with its diff and evidence when automatic promotion lacks sufficient independent held-out validation or held-out improvement. A same-project authenticated reviewer may promote it only while its source version remains current. See `apps/api/src/db/prompt-optimizations.ts`.
- **Dataset** — project-scoped collection whose immutable public identity is a project-local slug. Name, description, and tags have a separate lifecycle revision; one shared revisioned draft is the only mutable item workspace. Legacy UUID item routes remain temporary compatibility adapters. See `docs/05-unified-dataset-workflow.md`.
- **Dataset draft** — one project-scoped editable workspace for the next Dataset version. Its revision is returned as an ETag-compatible value and stale writes, deletes, and publication return the current revision plus a field-level diff rather than overwriting or auto-merging another curator's changes. Draft item UUIDs are public identities; their separate `item_key` is only the draft's editable stable key. See `apps/api/src/db/datasets.ts`.
- **Dataset draft item curation** — a versioned validation, review, ordering, and revision-history record for one draft item. History retains the durable Dataset identity, uses the published snapshot UUID after publication, includes the action Actor ID, and is read-only. Any write carrying Trace or Observation provenance rereads that same project-scoped source on the server and retains only redacted content; capture never publishes a Dataset. See `apps/api/src/routes/datasets.ts` and `infra/db/migrations/0070_dataset_draft_item_revision_history_retention.sql`.
- **Dataset curation idempotency record** — a project/Actor/operation/key replay record whose persisted target `dataset_id` prevents an import or capture retry from replaying for another Dataset after a draft is published, discarded, or archived. Migration `0069_dataset_curation_idempotency_audit_recovery.sql` recovers legacy targets only from unambiguous immutable audit history. See `infra/db/migrations/0068_dataset_curation_idempotency_target.sql`.
- **Dataset version** — immutable, ordered snapshot of a Dataset’s schema and item payloads. `GET /v1/datasets/by-slug/{slug}/versions/{version}?project_id=<UUID>` returns the complete ordered snapshot with safe trace/observation provenance; the version list remains summary-only and returns the same non-disclosing 404 contract for absent or out-of-project slugs. New Experiments resolve and retain one concrete version before task queueing; historical Experiment rows remain explicitly `legacy_unversioned` when their original input cannot be proven. Display form: `slug@version`. See `apps/api/src/db/experiments.ts` and `docs/05-unified-dataset-workflow.md`.
- **Dataset retention hold** — an active, project-scoped operator record preventing Dataset tombstoning and automated Dataset retention deletion. It is retained until explicitly released and does not remove immutable versions or historical run evidence. See `infra/db/migrations/0073_dataset_collaborative_lifecycle_governance.sql`.
- **Dataset item** — one JSON input/reference pair in a Dataset. Optional `source_trace_id` and `source_observation_id` preserve the production trace origin for regression workflows. Published snapshots and draft rows each use UUID item identities; an arbitrary draft `item_key` is never presented as a UUID ID. `GET /v1/datasets/{id}/items?project_id=<UUID>` shows the shared draft when present; `GET /v1/datasets/{id}/published-items?project_id=<UUID>` is the immutable execution view. Retained `POST /v1/datasets/{id}/items` uses JSON-body `project_id` (optional matching query), and `DELETE /v1/datasets/{id}/items/{itemId}?project_id=<UUID>`.
- **Evaluation** — a stable project-scoped named identity with one revisioned Definition draft and immutable published Definition Versions. Its canonical slug is neither UUID-shaped nor the reserved `compatibility` route name; UUID detail access remains a read-only compatibility selector, while every mutation requires the canonical slug. A Definition Version binds an immutable Dataset Version, deterministic sampling, versioned typed evaluator mappings, configured-LLM target selector, execution defaults, bounded cost/time limits, and thresholds; publication is hash-idempotent and does not execute a run. Evaluations can be archived, restored, then irreversibly tombstoned without deleting retained definitions or audit evidence. API: `/v1/evaluations`. See `apps/api/src/db/evaluations.ts`.
- **Evaluation Run** — an admitted execution of one immutable Evaluation Definition Version against its resolved Dataset Version. Admission stores the target, evaluator, execution defaults, thresholds, deterministic sample, per-item snapshot, accepted provider/model pair, active-run/requested-sample-size/provider-call bounds, request hash, and idempotency key before queueing the linked Experiment. The requested sample-size bound is checked before items are materialized, so a smaller Dataset Version can produce a lower selected count. Its task ledger is durable, project-scoped, bounded by leases/heartbeats and retry attempts, atomically charges each provider call before dispatch, and records safe result/evaluator evidence plus linked trace IDs. Lifecycle status and content-free events are available through `GET /v1/evaluation-runs/{id}`, cancellation/retry actions, and replayable SSE using `Last-Event-ID`. Repeating the same project-scoped request replays the exact stored input snapshot, including its ordered item fields; a missing snapshot fails closed. Replay does not create another Experiment or benchmark run. Historical Experiments and benchmark records remain explicit `legacy_ad_hoc` compatibility data; all current start routes require admission fields.
- **Evaluation Run evidence** — bounded, read-time-redacted inspection data for a Run. It includes pinned inputs, ordered item input/expected/output payloads, evaluator scores and rationale, task/result errors, provenance, trace IDs, cost, timing, and redaction indicators. `GET /v1/evaluation-runs/{id}` returns a bounded first page; `/evidence` provides deterministic project-scoped pagination. SSE lifecycle events are notifications, not a complete evidence history.
- **Evaluation Gate** — project-scoped release or CI admission authorized by an Admin approval for one immutable Evaluation Definition Version and its exact Dataset Version. Approval, revocation, supersession, invocation, and terminal outcome events are content-safe and append-only; a revoked approval cannot authorize new work. `release_gate_manage` is Admin-only, while inspection is project-scoped read access. See `docs/evaluation-gates.md`.
- **Evaluation Run comparison** — an observational comparison of two project-scoped Runs. Target changes are reportable baseline/candidate differences; Definition Version, Dataset Version, evaluator contract, execution defaults, thresholds, and sample identity must match before score/cost/duration deltas are emitted. Failed or cancelled Runs remain inspectable but return a null delta; incompatible or legacy contracts are refused rather than presented as equivalent. A valid comparison does not establish causal improvement.
- **Evaluation Definition Version** — the immutable, content-hashed published configuration of an Evaluation. Published versions cannot be generically edited or deleted; use the ETag-protected Evaluation draft to curate a later version. `GET /v1/evaluations/{slug}/versions/{version}` is read-only inspection and returns the stored publishing Actor ID as `published_by`, never a substituted subject. Pre-contract snapshots are explicitly returned as `definition_contract: "legacy_untyped"`, retaining their original JSON, absent typed fields, and stored hash. Legacy Experiments and benchmark suites are shown only as `legacy_ad_hoc` structural links through `/v1/evaluations/compatibility` and never gain invented historical inputs or evidence. See `infra/db/migrations/0076_evaluation_definition_contract_audit_integrity.sql`.
- **Experiment** — project-scoped compatibility view over an Evaluation Run's linked execution record. New starts require a JSON body with `project_id`, `dataset_id`, Evaluation identity/version, and idempotency key; they admit an immutable Run before tasks are queued and expose no mutable execution configuration in Experiment responses. Pre-version rows remain visibly `legacy_unversioned` rather than being assigned a fabricated historical snapshot. Claim, provider execution, persistence, tracing, completion, and restart recovery require the durable requesting Actor to retain execute access; unbound historical runs are cancelled. Retained `POST /v1/experiments` is body-scoped; list/detail/results/summary/events/cancel compatibility aliases require `?project_id=<UUID>`.
- **Legacy experiment item-link quarantine** — content-free PostgreSQL record of a historical task or result whose mutable `dataset_item_id` belongs to a different Project than its Experiment. Migration `0064_legacy_dataset_item_project_scope.sql` quarantines and removes the unsafe link, cancels affected active work, and prevents new cross-Project legacy links with composite foreign keys.
- **Benchmark suite** — project-scoped, longitudinal evaluation definition backed by a grounded golden Dataset whose items all provide expected outputs. Each run records its model/prompt label and ranks against prior runs. API: `/v1/benchmarks`.
- **Score** — numeric measurement on a trace or experiment item, keyed by `name`.
- **Feedback** — immutable `human.feedback` Score plus mutable project-scoped review state; negative `new` feedback appears in `/feedback` Needs review. Promotion appends a provenance-linked Dataset draft item rather than mutating a published Dataset. API: `/v1/feedback`.
- **Governance policy version** — immutable project-scoped retention and ingress-redaction configuration. Each Project receives an audited automatically approved 30/90/90, no-redaction baseline; later Project-specific versions still require approval, and equivalent content is hash-idempotent. API/UI: `apps/api/src/routes/governance.ts`, `infra/db/migrations/0105_governance_policy_defaults.sql`, `/governance`.
- **Retention run** — one bounded, project-scoped application of an approved governance policy. Its stored evidence has IDs, safe counts, status, and timings only; it never includes deleted source data. Summaries are available through `/v1/governance/retention/runs` and `/governance`. See `infra/db/migrations/0029_governance_policies.sql`.

## Storage roles

- **Postgres 16** — relational: agents, prompts, datasets, experiments, scores, projects.
- **ClickHouse 24** — OLAP: `traces`, `observations`. Partitioned by month; skip + bloom + tokenbf_v1 indexes.
- **Valkey 8** — event bus pub/sub fan-out (wire-compatible Redis). Future: BullMQ queues, rate-limit.

## Ingest

- **OTLP** — `POST /v1/otel/v1/traces`. Accepts OTel + `gen_ai.*` + OpenInference attrs and generation-only prompt provenance (`glasshouse.prompt.id`, `.version`, `.content_hash`). Per span: classify, sanitize metadata, write to ClickHouse, publish to bus (`trace.created` / `observation.created`). See `docs/03-otel-ingest.md`.

## Conventions

- **Agent Introspection Report:** one immutable, references-only `client_reported` report for an existing Evaluation Run task invocation; supplementary evidence, not verified execution or an Agent Registry record (`docs/agent-introspection-contract.md`, `apps/api/src/schemas/agent-introspection.ts`).
- **Run-item scope quarantine:** safe identity metadata retained when a historical task Run-item relationship cannot be deterministically remapped to an unoccupied matching Dataset item; the invalid Run association is removed rather than guessed (`infra/db/migrations/0091_agent_introspection_run_item_scope.sql`, `0092_agent_introspection_scope_pair_integrity.sql`).

- **observation** (not span) for the data-model concept.
- **trace** (not request/run/session) in observability context.
- **generation** (not "LLM call") when `type` matters.
- **manifest** (not "agent config/spec").
- **organization** (not tenant) for the authenticated top-level scope; **project** (not organization) for its workspace and data scope.
- **score** (not metric/eval) in the scoring context.
- **SSE** for Server-Sent Events; avoid "websocket/live feed/push".
- **OTLP** for OpenTelemetry Protocol.
- **Valkey** (not Redis) — wire-compatible, but we ship Valkey.

## Keeping this file up to date

Add or edit a term here whenever:

1. **You introduce a new entity, route, page, or stored field** that has a user-facing name. Add it under the right section with a one-line "what it is" + a file pointer.
2. **You rename something** in the UI, API, or DB. Update this file in the same PR — keep the legacy alias here so search still finds it.
3. **You notice two names used interchangeably** for the same thing. Pick one (prefer the more specific / data-model name), add both to this file, then fix the codebase in the same PR.
4. **You add a classification rule** to `classifySpanType` (or change one). Update the `type` table above.

Style rules:

- Short. One line per entry if possible. Tables for taxonomies.
