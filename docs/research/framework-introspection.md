# Agent Eval Platform: Framework Introspection & Registration Patterns

> Research deliverable. Goal: identify the lowest-friction way to let users on Agno / LangGraph / CrewAI / Pydantic AI / Mastra / Vercel AI SDK / Letta / OpenAI Agents SDK "register" an agent with our eval platform and have us capture its full config (name, model, instructions, tools, knowledge, storage) for version binding — without making them hand-author a YAML manifest.

---

## 1. Agno deep-dive

### What is Agno?

Open-source Python SDK for building agent platforms (formerly Phidata). 41k GitHub stars. The pitch is: "Build, run, and manage agent platforms" — agents, teams, workflows, with storage, memory, knowledge, RBAC, observability, OpenTelemetry, MCP, A2A, and an AgentOS control plane. Agno agents run as services, not just in-process.

### `Agent` constructor (verbatim from `agno/agent/agent.py`)

It is a `@dataclass(init=False)` — meaning the real `__init__` is hand-written in `_init.py`. Constructor accepts ~100 keyword arguments. Key ones:

### ⚡ Critical finding: Agno already has built-in introspection

```python
config = agent.to_dict()              # serializes EVERYTHING
recreated = Agent.from_dict(config)   # reconstructs from it
```

- `to_dict()` returns a Python dict with `name`, `model`, `instructions`, `tools` (as config dicts), `knowledge`, `db`, `memory_manager`, `session_state`, `hooks`, `reasoning`, `output_schema`, etc.
- `Agent.from_dict()` rebuilds the object. Tools are stored as **references** resolved at load-time through a `Registry`. Tool source code is NOT serialized — only names/configs.
- Module-level helpers `get_agent_by_id()` / `get_agents()` load from DB by `component_id`, `version`, or `label` — Agno has **first-class versioning** baked in (`component.current_version`, `agent._version`, `agent._stage`).
- Documented example: https://docs.agno.com/examples/agents/advanced/agent-serialization

**Implication**: For Agno, we don't need to design an "introspection API." We can call `agent.to_dict()` and have a complete manifest in one call. The cost: tools are references, not code; the platform must resolve references (or run in the user's env).

## 2. Per-framework introspection table

"How much can we extract from a single Agent object via attribute access / standard methods?"

| Framework | Object | `name` | `model` | Instructions (system prompt) | Tools (enumerable?) | Knowledge base | Storage / memory | Output schema | Output method | Built-in serialize? | Pitfalls |
|---|---|---|---|---|---|---|---|---|---|---|---|
| **Agno** | `agno.agent.Agent` (dataclass) | ✅ `.name` | ✅ `.model` (Model obj) | ✅ `.instructions` (str/List/Callable) | ✅ `.tools` (List); each is `Toolkit` / `Function` / dict; introspect `name`, `description`, `parameters` | ✅ `.knowledge` (KnowledgeProtocol) | ✅ `.db`, `.memory_manager`, `.session_state` | ✅ `.output_schema` | `agent.print_response()` / `agent.arun()` | ✅ **`agent.to_dict()` / `Agent.from_dict()`** | Tools are **registry references**, not code. Some fields are Callables (instructions, knowledge, tools) — can't serialize the body, only the name. |
| **LangGraph** | `langgraph.graph.StateGraph` (builder) → `.compile()` → `CompiledStateGraph` | ❌ no `.name` on graph | ❌ no model at graph level | ❌ prompts live **inside** node functions | ⚠ nodes are callables; tool list = node names + inspect node source | ❌ no first-class knowledge (use LangChain `VectorStore` inside nodes) | ✅ checkpointer (`MemorySaver`, `PostgresSaver`) | ✅ `state_schema` (TypedDict) | `.invoke()`, `.stream()` | ❌ no `to_dict()`; must walk `.nodes`, `.builder`, read the `langgraph.json` | Dynamic graphs (factory functions) are hard to capture at static time. `langgraph.json` is the closest manifest. |
| **CrewAI** | `crewai.Agent` + `Task` + `Crew` | ✅ `.role` | ✅ `.llm` | ✅ `.goal`, `.backstory`, `Task.description`, `Task.expected_output` | ✅ `.tools` (List[BaseTool]); `tool.name`, `tool.description` | ⚠ not first-class; pass via custom tool | ⚠ memory via `Crew.memory=True` | `Task.output_pydantic` / `output_json` | `crew.kickoff()` | ⚠ partial — `crewai crew` CLI can dump YAML; no public `.to_dict()` | Role/goal/backstory are intentionally chunky prose — multi-line strings make manifests ugly. |
| **Pydantic AI** | `pydantic_ai.Agent` (generic) | ⚠ uses type params `Agent[DepsT, OutputT]`, not `.name` | ✅ `.model` | ✅ `.instructions` (str or Callable taking `RunContext`) | ✅ `.tools` (list of `Tool`); introspect via `agent._function_toolset` | ❌ not first-class | ⚠ deps via `_deprecated_kwargs`, RunContext | ✅ `.output_type` (Pydantic model) | `agent.run_sync()` / `agent.run()` | ❌ no built-in `to_dict()`; must walk `_internal` attributes (private API) | Generic over `DepsT`/`OutputT` — type-only; can't always serialize deps. |
| **Mastra** | `@mastra/core/agent`'s `Agent` class (TS) | ✅ `name` | ✅ `model` | ✅ `instructions` (str) | ✅ `tools` (Record); each tool has `id`, `description`, `inputSchema` | ✅ `knowledge` (vector store wrapper) | ✅ `memory` (MemoryConfig) | ❌ output schema not first-class | `agent.generate()`, `agent.stream()` | ❌ no `.toJson()`; manual property walk | TypeScript — JSON.stringify works if you skip functions. |
| **Vercel AI SDK v6** | `ToolLoopAgent` (introduced v6) | ✅ `id` (required) | ✅ `model` | ✅ `instructions` (SystemModelMessage) | ✅ `tools` (Record) | ❌ not first-class | ❌ not first-class | ✅ `output` (Output spec) | `agent.generate()` / `.stream()` | ❌ no built-in serialize; DevTools emits traces only | Recently released; pre-v6 it's custom agent loops — not introspectable at all. |
| **OpenAI Agents SDK** | `agents.Agent` | ✅ `name` | ✅ `model` (str or Model) | ✅ `instructions` (str or Callable) | ✅ `tools` (List[Tool]) | ❌ | ⚠ `session` passed at Runner level | ✅ `output_type` (Pydantic) | `Runner.run()` | ❌ no `to_dict()`; has `agent.as_tool()` for nested use | Handoffs (`agent.handoffs`) point at other agents — graph of objects. |
| **Letta** | `Letta` client → `AgentState` (server-side) | ✅ `AgentState.name` | ✅ `AgentState.llm_config` | ✅ `AgentState.system` | ✅ `AgentState.tools` | ✅ memory blocks (`memory.blocks`) | ✅ all persisted in DB | ⚠ via tool args | `client.agents.create.retrieve()` | ✅ **the server IS the source of truth** — `client.agents.export()` returns full config | Server-defined; agent lives in Letta cloud/self-host, not in user's Python process. |
| **AutoGen** | `autogen_agentchat.agents.AssistantAgent` | ✅ `name` | ✅ `model_client` | ✅ `system_message` (str or list) | ✅ `tools` (List[BaseTool]) | ❌ | ✅ `memory` | ❌ | `.on_messages()` | ❌ no built-in serialize | Multi-agent: `RoundRobinGroupChat`, `SelectorGroupChat` — config is the group, not the agent. |
| **DSPy** | `dspy.Module` / `dspy.Predict` / `dspy.ReAct` | ✅ `__name__` | ✅ module's LM | ✅ signatures (input/output fields with descriptions) | ✅ module's tools | ❌ | ❌ | ✅ via signature | `module(...)` | ❌ signature is the "manifest" — it's the closest thing | Signatures are short strings; the prompt is **compiled** from them, not stored verbatim (DSPy optimizers mutate it). |
| **Raw OpenAI/Anthropic client** | `openai.OpenAI()` + custom loop | ❌ no agent object | ✅ client.model | ✅ your string var | ✅ your list var | ❌ | ❌ | ❌ | custom | ❌ | Nothing to introspect — user must hand-declare everything. |

**Key takeaways**:

1. **Agno, Letta, and CrewAI** have the richest first-class introspection. Agno wins on declarative fields; Letta wins because the server owns the agent.
2. **LangGraph** is intentionally bare-bones — no name, no model at graph level, prompts hidden in functions. This is the **hardest** framework to auto-discover a manifest from.
3. **Pydantic AI, Mastra, Vercel AI SDK, OpenAI Agents SDK** have all the fields as accessible properties, but no built-in `to_dict()`. A simple property walk + JSON.stringify would work.
4. **Vercel AI SDK v6's `ToolLoopAgent`** is the most recent "framework-native agent object" and is intentionally designed to be introspectable.
5. **Custom loops / raw clients** are un-introspectable. These users must hand-author.

## 3. Per-registration-pattern table

"How does the user tell the platform about their agent?"

| Pattern | Examples | Authoring friction | Version binding | Framework coverage | Best for |
|---|---|---|---|---|---|
| **Code-first wrapper** (`Eval({task: fn})`) | Braintrust `Eval(task=lambda x: agent(x))`, LangSmith `evaluate(target_fn)`, Phoenix `Experiment(task=callable)` | 🟢 Low — one lambda | ⚠ Weak — version = whatever's at `agent.__module__` git SHA; no schema | 🟢 Universal — works with anything callable | Dev iteration, CI evals, local evals |
| **Declarative YAML/JSON manifest** (`agent.yaml`) | Maxim "endpoint config", Agent Format `.agf.yaml`, CrewAI YAML, `langgraph.json`, Google ADK `agent.yaml` | 🔴 High — must duplicate what code already says | 🟢 Strong — YAML in git = exact version | 🔴 Per-framework schemas diverge | Production deployment, governance, governance review |
| **Auto-discovery** (introspect user's Agent object) | (Proposed) Agno `agent.to_dict()`, Braintrust `auto_instrument()` (OpenTelemetry), `setup_crewai()`, `setup_langsmith()` wrappers, AgentOps one-line tracker | 🟢 Lowest — one decorator or one function call | ⚠ Medium — version = git SHA + a content hash of the captured config | ⚠ Requires framework-specific adapter | Greenfield adoption, "just works" onboarding |
| **HTTP endpoint + body template** | Maxim AI `HTTP Endpoint Evaluation`, Braintrust `setup_anthropic` style, webhooks | 🟡 Medium — must deploy an HTTP wrapper | ⚠ Weak — endpoint is versioned separately | 🟢 Universal — anything with an API | No-code agents, vendor SaaS (Glean, Bedrock), 3rd-party APIs |
| **Hosted runtime** (deploy agent into platform) | LangSmith Deployment, Braintrust Sandbox (Modal-based), Letta Cloud, Agno AgentOS | 🔴 Highest — must port/deploy your agent | 🟢 Strongest — platform owns versioning | 🔴 Requires framework compatibility with the runtime | Production scale, RBAC, multi-tenant |
| **CLI scaffolding** | `mastra init`, `crewai create`, `agentregistry` CLI, `bt setup` | 🟡 Medium — generate boilerplate that wraps your agent | 🟢 Strong — generated code is in your repo | ⚠ Framework-specific generators | First-run onboarding, opinionated workflows |

### Existing precedents for auto-discovery

- **Braintrust `auto_instrument()`** (one function call) auto-instruments OpenAI, Anthropic, LangChain, LangGraph, CrewAI, Pydantic AI, AutoGen, AgentScope, Mastra, Google ADK, Strands, LiveKit Agents. It captures **traces** (LLM calls, tool calls), not static config.
- **Braintrust `setup_crewai()`** / `setup_langsmith()`** — explicit wrappers for one framework.
- **OpenTelemetry auto-instrumentation** — Java agent, Python/Node hook loaders; zero-code observability for OpenAI, Anthropic, FastAPI, etc. via `OTEL_EXPORTER_OTLP_*` env vars. Closest analogue to what we want for static config.
- **AgentOps one-line** — `agentops.init(api_key=...)` then any framework call is traced. Tracing, not config.
- **OpenInference semantic conventions** — standard span attributes (`openinference.*`) so any OTel-instrumented agent becomes "describable" to Phoenix / Arize.

## 4. Synthesis: The right SDK API for "tell me about your agent"

**Goal**: auto-generate the manifest from existing code, à la OpenTelemetry auto-instrumentation.

### The shape of the API

A single function with a per-framework adapter strategy pattern, falling back gracefully:

```python
# eval_platform/introspect.py

from typing import Any, Protocol, runtime_checkable

@runtime_checkable
class Describable(Protocol):
    """Optional. Frameworks that support it implement this protocol."""
    def describe(self) -> dict: ...

def introspect(agent: Any, *, source: str = "auto") -> AgentManifest:
    """
    Returns a structured AgentManifest capturing the agent's full config
    for version binding + later eval replay.

    'source' is "auto" | "manual" | "http".
    """
```

**Five implementation tiers**, in order of preference:

### Tier 1 — protocol method (preferred)

```python
class AgnoAdapter:
    def introspect(self, agent):
        cfg = agent.to_dict()  # first-party method
        return AgentManifest(
            framework="agno",
            framework_version=agno.__version__,
            content_hash=hash(cfg),
            config=cfg,  # raw config preserved
            captured_at=utcnow(),
        )
```

Frameworks that expose `to_dict()` / `describe()` / `as_dict()`: use it directly. Agno, Letta, CrewAI (via `crew export`), Pydantic AI (via internal walk).

### Tier 2 — adapter per framework (property walk)

```python
class PydanticAIAdapter:
    def introspect(self, agent):
        # Walk private attributes — wrapped behind a feature flag
        return AgentManifest(
            framework="pydantic_ai",
            config={
                "name": getattr(agent, "name", None),
                "model": agent.model.model_name if hasattr(agent, "model") else None,
                "instructions": _call_if_callable(agent.instructions),
                "tools": [_tool_to_dict(t) for t in agent.tools],
                "output_type": agent.output_type.__name__ if agent.output_type else None,
            },
            ...
        )
```

### Tier 3 — generic AST/static analysis (fallback)

For LangGraph, where the agent is a graph + node functions, we walk:

1. `langgraph.json` (the deployment manifest) → entry point + graph path
2. AST of the graph file → extract `add_node("name", fn)`, `add_edge(...)`, system prompts inside fns, model bindings
3. Tool references resolved via import graph

This is "good enough" version binding; full semantic fidelity is impossible without execution.

### Tier 4 — runtime probing

For agents that build themselves at runtime (factory functions, dynamic tool registries), introspect after a single dry-run:

```python
agent = build_my_agent()  # user runs the factory
# After construction but before .invoke():
manifest = introspect(agent)
# We capture config + a content hash + git SHA of the source file
```

### Tier 5 — manual manifest

For custom loops and un-introspectable stacks, fall back to a hand-authored `agent.yaml`, **but only as a last resort**.

## 5. Synthesis: Lowest-friction integration per framework

| User's framework | Recommended integration | Why |
|---|---|---|
| **Agno** | `manifest = agno_adapter.introspect(agent)` calling `agent.to_dict()` | Framework literally gives you `to_dict()` / `from_dict()` and per-version DB storage. Zero-friction. |
| **LangGraph** | Read `langgraph.json` + AST-walk the graph module + recommend they also `from langsmith import traceable` | No central object; deployment manifest is the closest thing. Pair with trace data. |
| **CrewAI** | `manifest = crewai_adapter.introspect(crew)` + use `crewai crew` CLI's YAML export as cross-check | Agent + Task + Crew form a triangle; all 3 are introspectable. The CLI dumps a YAML you can use as ground truth. |
| **Pydantic AI** | `manifest = pydantic_ai_adapter.introspect(agent)` walking `agent.tools`, `agent.model`, `agent.instructions` | All fields are plain properties. No built-in serializer, but a 30-line adapter suffices. |
| **Mastra** | `manifest = mastra_adapter.introspect(agent)` walking JS properties + `JSON.stringify(agent, replacer=skipFunctions)` | TS objects JSON-stringify cleanly if you skip functions. |
| **Vercel AI SDK (v6+)** | `manifest = ai_sdk_adapter.introspect(agent)` from `ToolLoopAgent` | `id`, `model`, `instructions`, `tools`, `output` are all top-level fields. Pre-v6 = custom loop, fall back to manual. |
| **OpenAI Agents SDK** | `manifest = openai_agents_adapter.introspect(agent)` walking `name`, `instructions`, `tools`, `handoffs` | All introspectable. Handoffs are a graph of agents — capture recursively. |
| **Letta** | `manifest = client.agents.export(agent_id)` | The server IS the source of truth. One API call. |
| **AutoGen** | `manifest = autogen_adapter.introspect(agent)` + capture the `GroupChat` topology | Multi-agent topology needs recursive walk. |
| **Custom / raw client** | `manifest = author_yaml()` or use the HTTP-endpoint fallback | Nothing to introspect. |

**Tier-1 adapters we should ship day one** (in priority order): **Agno, Pydantic AI, OpenAI Agents SDK, CrewAI, Mastra, Vercel AI SDK v6**. Together these cover ~80% of new agent code in 2025-2026.

## 7. Recommendation: the **layered** approach

**Don't pick one pattern — pick all five, with a clear hierarchy**:

```
1. INTROSPECT FIRST (auto-discovery, framework-specific adapters)
   └─ Agno, Letta, CrewAI, Pydantic AI, Mastra, Vercel AI SDK, OpenAI Agents SDK
   └─ Walks object attributes + uses to_dict() where available
   └─ Captures content hash + git SHA → strong version binding

2. FALL BACK TO HTTP ENDPOINT (Maxim-style)
   └─ For black-box deployments, SaaS agents, no-code platforms
   └─ Weak version binding (endpoint version) — but universally compatible

3. FALL BACK TO CODE-FIRST WRAPPER (Braintrust Eval-style)
   └─ For dev iteration, CI evals
   └─ Version = git SHA of wrapper module + content hash of agent pickle/serialized

4. FALL BACK TO DECLARATIVE YAML (Kubernetes-style)
   └─ Only when introspection is impossible AND HTTP is undesirable
   └─ Strong version binding (YAML in git) but high friction
   └─ Reserve for governance/review workflows, not dev-time eval

5. HOSTED RUNTIME (LangSmith/Braintrust Sandbox/Agno AgentOS)
   └─ For production scale, multi-tenant, RBAC
   └─ Out of scope for the eval platform's "registration" primitive
```

### The "tell me about your agent" API (final form)

```python
from eval_platform import introspect

# One-liner. Works for ~80% of frameworks via adapters.
manifest = introspect(agent)

# Returns:
AgentManifest(
    framework="agno",          # detected
    framework_version="2.6.22",
    agent_id="research-agent-v3",
    name="Research Agent",
    model={"provider": "openai", "name": "gpt-5"},
    instructions=["You are a research analyst.", "Always cite sources."],
    tools=[
        {"name": "duckduckgo_search", "kind": "toolkit", "source": "agno"},
        ...
    ],
    knowledge={"type": "vector_db", "backend": "lancedb", "table": "docs"},
    storage={"type": "sqlite", "path": "tmp/agent.db"},
    output_schema="ResearchReport",
    config_raw=agent.to_dict(),   # preserved for replay
    content_hash="sha256:...",
    source_file="agents/research.py",
    source_git_sha="abc123",
    captured_at=utcnow(),
    introspection_method="agno.to_dict",   # which path we took
)
```

### Why this is the right shape

1. **`introspect()` does the maximum automatically, then degrades.** No user has to author a YAML until we've tried harder than they have.
2. **`config_raw` preserves the framework-native dump.** Even if our adapter is wrong, we have the original — replay is possible.
3. **`content_hash` + `source_git_sha` together = strong version binding.** Two agents with same content_hash but different git SHAs are the same; two with same SHA but different hashes are different (someone edited live).
4. **`introspection_method` is honest.** If we used the `to_dict()` fast path, we say so; if we had to AST-walk, we say so; users know what fidelity they got.
5. **The function returns, doesn't push.** Eval platforms that push data (OTel auto-instrumentation) are powerful but scary. A pull-style `introspect()` is debuggable, testable, and can be called from CI.

### Anti-patterns to avoid

- ❌ Forcing all users to write `agent.yaml` — high friction, redundant with code.
- ❌ Trying to be framework-agnostic by inventing a universal Agent IR. Every framework has different semantics; lossless translation is impossible. Capture the framework-native config + a normalized overlay.
- ❌ Auto-instrumentation that mutates the user's agent (OTel-style monkey patching) — users lose trust. Provide a pure read function instead.
- ❌ Requiring hosted runtime for "real" version binding — most teams will never deploy into our runtime. The content hash + git SHA gives equivalent guarantees.
- ❌ Designing the manifest before the introspectors. The introspectors will tell you what fields are stable, which are noisy, and which are framework-specific. Build them in parallel.

## TL;DR (the deliverable)

- **The right SDK API is `introspect(agent)`** — a pull-style, framework-adapted function that returns a structured `AgentManifest` containing the full config, a content hash, and provenance. Auto-discovery for the 6 frameworks with richest introspection (Agno, Letta, Pydantic AI, CrewAI, OpenAI Agents SDK, Mastra/Vercel AI SDK v6). HTTP endpoint fallback for black-box. Hand-authored YAML as the last resort.
- **Agno is the easiest case** — `agent.to_dict()` is literally the manifest. Agno is also the only major framework with built-in versioning (`_version`, `_stage`, `component_id` + `label`).
- **LangGraph is the hardest case** — no name, no model at graph level, prompts hidden in node functions. Fall back to `langgraph.json` + AST walk.
- **The `agent.yaml` should NOT be the primary primitive.** It is the universal fallback when introspection fails. Ship adapters first; treat YAML as the offline override.
- **Version binding comes from `content_hash(config_raw) + source_git_sha + framework_version`.** That's stronger than YAML-in-git because it captures live mutations a YAML author would miss.
